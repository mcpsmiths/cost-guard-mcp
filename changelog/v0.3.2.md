# v0.3.2 — 2026-09-22

Another metadata-only patch, found by inspecting the README badge row rendered on
GitHub after the v0.3.1 fix.

### Fixed

- `pyproject.toml` had no `classifiers` field, so the published PyPI package had
  `classifiers: []` (confirmed via `https://pypi.org/pypi/cost-guard-mcp/json`) —
  shields.io's `pypi/pyversions` badge reads `Programming Language :: Python :: X.Y`
  trove classifiers specifically, not `requires-python`, so README's "python" badge
  rendered "missing" instead of a real version. Added `Programming Language :: Python
  :: 3` and `Programming Language :: Python :: 3.12`.
- Deliberately did NOT claim 3.13 or 3.14 support: `.python-version` pins `3.12`,
  `tests.yml` only runs against it, and the Dockerfile's base image is
  `python3.12-trixie-slim`. `requires-python = ">=3.12"` permits newer interpreters to
  install the package, but nothing in this project actually verifies them.
