# v0.3.0 — 2026-09-18

A CRITICAL CVE fix, a real Snowflake pricing-correctness bug (silently wrong for the now-common
default case), a fix to make MCP-level cancellation actually work, and a new opt-in
observability surface — plus signed release artifacts, so this release itself is the first to
be verifiable end-to-end. Every fix below was live-verified against a real Snowflake/Databricks
account, not just unit tests; BigQuery and one Databricks pricing question had no live
credentials available and were instead resolved through cited research (see Known limitations).

### Added

- Snowflake cost estimates now detect warehouse generation (Gen1 vs. Gen2) via a
  non-privileged `SHOW WAREHOUSES` + `CURRENT_REGION()` lookup and price Gen2 at its real,
  higher per-hour credit rate instead of silently assuming Gen1 for every warehouse. Live-
  verified against a real trial account: its default warehouse (`COMPUTE_WH`) is genuinely
  Gen2 on AWS, and the fix correctly detected it and applied the Gen2 rate.
- Structured, secrets-free logging (always on) at the two universal tool/warehouse-call
  choke points — every tool call now logs its name, outcome, and elapsed time; every
  warehouse-client failure logs the engine and the already-redacted safe message.
- Opt-in OpenTelemetry tracing, gated on `OTEL_EXPORTER_OTLP_ENDPOINT` — the `mcp` SDK's
  built-in `OpenTelemetryMiddleware` ships on by default but is a no-op until an exporter is
  registered; a deployment that never sets the env var never needs the new `otel` dependency
  group installed at all.
- Signed release artifacts: PyPI PEP 740 attestations (`astral-sh/attest-action`) and a
  GitHub Release SLSA provenance bundle (`actions/attest-build-provenance`), closing the
  OpenSSF Scorecard Signed-Releases gap.
- `server.json` now declares a `title` and a full `environmentVariables` array (all 12 vars
  this server reads for credentials/config), and each of the four MCP tools has a
  human-readable `title` annotation.
- Databricks pricing extended to `5X-Large` (still Public Preview — see Known limitations).
- Dev tooling migrated to PEP 735 `dependency-groups`; `.python-version` pinned to match the
  Dockerfile's base image.

### Fixed

- **CRITICAL**: `snowflake-connector-python`'s floor was `>=3.12.0`, which structurally
  permitted GHSA-5cc2-282f-jjq2 / CVE-2026-15925 (a TLS hostname-verification bypass allowing
  on-path credential/query/staged-file interception and arbitrary SQL execution). Raised to
  `>=4.7.1`. Live-verified: the new floor connects cleanly against a real account.
- `run_query_bounded`'s MCP-level cancellation was inert — a client-sent
  `notifications/cancelled` had zero effect until the existing ~120s per-engine watchdog
  fired regardless, because the tool wrapper's implicit sync-wrapping shielded it from
  cancellation (`anyio.to_thread.run_sync`'s default `abandon_on_cancel=False`). The tool is
  now `async` and explicitly passes `abandon_on_cancel=True`, so a cancellation is prompt at
  the MCP bookkeeping level (the underlying warehouse call still runs until the watchdog
  fires — see Known limitations, unchanged from before this fix).
- `as_tool_error` was sync-only; wiring the fix above surfaced that it would have silently
  no-op'd an async tool body (returning an unawaited coroutine instead of running it) — now
  supports both sync and async wrapped functions.
- BigQuery `dry_run()` could report a PRECISE $0.00 estimate for a query against a
  row-level-security-protected table — BigQuery's own documented dry-run behavior always
  returns 0 bytes for RLS-masked tables, and this estimate previously passed straight through
  the fail-closed cap logic with nothing to catch it. Now caveated.
- BigQuery remote-function / `ML.GENERATE_TEXT` (BigQuery ML remote-model inference) billing
  is now caveated — previously excluded from the byte-based dollar estimate with no warning
  at all, unlike the already-documented Snowflake Cortex-AI-cost exclusion.

### Known limitations

- Cancellation (this release's fix) only makes the MCP-level bookkeeping prompt — it does not
  itself stop the abandoned warehouse-side query any sooner than the existing per-engine
  watchdog (~120s). Wiring the cancel signal down into the watchdog thread to call the
  engine's own cancel method immediately is a separate, larger follow-up, not implemented
  here.
- The OpenTelemetry bootstrap has not been verified against a real OTel Collector — only via
  mocked-provider unit tests, since no live OTel endpoint was available.
- Databricks `5X-Large` DBU/hour rate is still sourced from a Databricks-employee community
  blog post, not the GA pricing table — re-confirmed 2026-09-18 that 5X-Large remains Public
  Preview and unpriced on both Databricks' own docs and Azure's Databricks pricing page.
- Whether BigQuery's `referencedRoutines` dry-run field actually populates at dry-run time
  remains unconfirmed — it is a real, documented API field, but no Google source states its
  dry-run availability either way, and no BigQuery credentials were available to check
  directly. It can never detect `ML.GENERATE_TEXT` regardless (BQML models are not routines),
  so the existing unconditional text heuristic stays as the only detection path for that case.
